emerge.

# Format

* Everything lives in the vault via **speki**; Markdown must conform to OKF.
  Interactive **HTML lessons** are kept in the vault too (under `lessons/`), which
  is fine — speki only validates the Markdown.
* Durable knowledge (mission, glossary, references, learning records) is Markdown
  so it stays LLM- and human-readable; lessons carry the interactivity.

# Teaching preferences

* Be concise and direct in conversation (sacrifice grammar for concision when
  reporting); lessons and vault documents stay well-written.
* Connect leadership ideas back to concrete engineering work — the learner is
  hands-on; avoid abstract theory floating free of practice.
* Cite high-trust sources in every lesson rather than asserting from memory.

# Reminders for the teacher

* Ground every lesson in the [mission](./mission.md); the through-line is
  *aiming for a lead promotion* — build both skill and evidence.
* Use retrieval practice and spacing; don't mistake in-the-moment fluency for
  durable retention.
* The highest-value external resource to obtain is the employer's actual
  lead/staff promotion rubric — keep nudging toward getting it.
